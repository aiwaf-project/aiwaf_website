How it works

  1. RunnerSends normal requests, simulated clients, and payloads.
  2. AIWAF proxyApplies runtime controls before forwarding.
  3. RedisShares supported state under isolated namespaces.
  4. ApplicationJuice Shop supplies a vulnerable baseline; the reference fixture supplies outcome assertions.

The sandbox repository owns Compose, proxies, fixtures, runners and dependency locks. The fifteen JavaScript/Python/Java integrations install published releases from npm, PyPI and Maven Central. No adjacent SDK checkout or GitHub source build context is used.

examples/sandbox/package-versions.json records the selected releases: Python AIWAF 1.1.8, aiwaf-rust 0.2.7, npm AIWAF 1.1.5, aiwaf-wasm 0.2.5, and Java 1.3.5. Build declarations and locks must agree with that inventory. PHP uses a separate Composer package and is excluded from the fifteen-runtime published-package runner.

Start contributing

Begin with one Express endpoint before building the full matrix. Small documentation fixes, a targeted dependency update, or a focused helper-test improvement make manageable first contributions. The contributor workflow explains tests, working directories, dependency review and PR evidence. The repository README is the command reference; these pages organize it by task.

Evaluate your build

Generate reports for the package versions, container images, and configuration you are testing. Run the validation workflow to check installed versions, normal traffic, SQL login outcomes, TLS, failures, and dependencies.

Passing implemented scenarios does not close an entire OWASP category. See coverage and assessment boundaries before making a security claim.
