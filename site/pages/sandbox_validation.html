Run the published-package workflow

Start all fifteen integrations using the tutorial. Build the separate audit image and prepare both assessment profiles and the public TLS root certificate:

docker compose --profile assessment-tools build aiwaf-audit-tools
docker compose --profile assessment --profile assessment-tls up -d --build security-fixture aiwaf-assessment assessment-tls
New-Item -ItemType Directory -Force examples/sandbox/assessment/.tls
docker compose --profile assessment --profile assessment-tls cp assessment-tls:/data/caddy/pki/authorities/local/root.crt examples/sandbox/assessment/.tls/root.crt
python examples/sandbox/run-published-packages.py

On POSIX shells use mkdir -p examples/sandbox/assessment/.tls instead of New-Item. Wait for Caddy to create its root certificate before copying it. This explicit trust file does not change host trust.

The runner verifies installed versions, then checks runtime hardening, smoke traffic, SQL login, payload observations, post-matrix SQL controls, extended reference/TLS outcomes, eight production proxy npm lockfiles, isolated outages and image advisories. PHP is excluded. Run suites sequentially to avoid build/scan load distorting request timeouts.

--verify-only checks installed versions only. --skip-image-scans omits Grype; it does not establish a clean image result or refresh previous image reports. The full runner has no resume option. Contributor unit tests are documented under operations.

Interpret each check

CheckWhat success establishesLimit
SmokeNormal/lowercase headers succeed; automation and excess traffic are denied; benign JSON login reaches the app.Not a complete attack evaluation. Burst checks need accepted and denied requests, so blanket blocking fails.
SQL loginTwo SQL payloads cannot issue a token; invalid credentials supply the control.Specific exploit outcomes only. Tokens are omitted.
Payload matrixAll selected observations complete without request errors.Exit 0 does not mean every payload was denied or every exploit prevented.
Reference fixtureStatus, response fields and state changes enforce each tested application rule.Application-owned controls; an unrelated WAF 403 cannot count as success.
npm/image auditAdvisory query and matched dependency findings are recorded.Package locations and exploitability still need triage.

The legacy attack suite classifies 403/405/409/429 as blocked; these statuses can come from another layer. Default legacy probes can also be rejected by header validation before payload inspection. A block percentage is not a demonstrated detection rate. The newer matrix uses browser headers except in scenarios designed to alter them.

Rate-limit and brute-force scenarios retain one public client IP throughout, then generate a fresh IP for the next scenario. Other probes rotate per request. Redis is not flushed, so retained reputation may reveal false positives after attack traffic.

Target one runtime or resume observations

python examples/sandbox/smoke-test.py --target django=http://127.0.0.1:3009 --burst-workers 16
python examples/sandbox/validate-login-bypass.py --target java=http://127.0.0.1:8080
python examples/sandbox/validate-runtime-matrix.py --exclude laravel --exclude symfony --exclude wordpress --output examples/sandbox/results_published_payload.json

The matrix's default per-request timeout is five seconds. --timeout changes that requirement; disclose any change when reporting results. --resume retains saved baselines and targets without errors, and reruns failed targets. Keep resumes within the same packages/configuration; the matrix alone does not verify package provenance.

Extended checks with TLS

Caddy exposes only loopback ports 8443/8444. Its internal CA stays in a dedicated Docker volume. Export the public root certificate; pass it explicitly to the runner without changing host trust.

docker compose --profile assessment --profile assessment-tls up -d --build security-fixture aiwaf-assessment assessment-tls
New-Item -ItemType Directory -Force examples/sandbox/assessment/.tls
docker compose --profile assessment --profile assessment-tls cp assessment-tls:/data/caddy/pki/authorities/local/root.crt examples/sandbox/assessment/.tls/root.crt
python examples/sandbox/assessment/run.py --extended --fixture https://localhost:8443 --fixture https://localhost:8444 --ca-file examples/sandbox/assessment/.tls/root.crt --tls-url https://localhost:8443 --tls-url https://localhost:8444 --npm-audit --local-runtime-scope --output examples/sandbox/results_published_owasp_extended.json

Tests require trusted TLS 1.2/1.3, rejection of old protocols, untrusted roots and incorrect hostnames. Client-side inability to test an old protocol is not_assessed, not a server pass. Both profiles are needed because TLS depends on the fixture/proxy. Caddy preserves synthetic client IPs for loopback assessment; that trust arrangement is not a production proxy policy.

For HTTP-only checks, use both --fixture http://localhost:8090 and --fixture http://localhost:3020 with --extended --allow-local-http. HTTP transport remains unassessed. Omitting --npm-audit leaves the advisory query unassessed.

Isolated failures and dependency scans

python examples/sandbox/assessment/outages.py --output examples/sandbox/results_published_outages.json
python examples/sandbox/audit-published-proxies.py --output examples/sandbox/results_published_npm_audits.json
python examples/sandbox/assessment/scan_images.py --output examples/sandbox/results_published_image_advisories.json
python examples/sandbox/assessment/render_report.py --prefix published

Outage tests run an isolated Express process with actual Redis/upstream connection refusals. They require generic 503 with no application call for Redis, and generic 502 for upstream failure. They do not stop shared Redis or demonstrate failover in all runtimes. Python outage behavior has separate SDK unit/HTTP regressions.

Serving Node images contain no npm/npx/Yarn. The audit tools image audits copied production manifests and locks. Do not use the legacy --include-sdk option with registry images: it expects the removed /opt/aiwaf-js installation. Proxy locks already include AIWAF dependencies.

Grype 0.120.0 is pinned by image digest, scans fifteen built images including OS packages, mounts the Docker socket and uses sandbox_grype_db for its advisory database. It exits 1 on high/critical findings or scan errors; lower findings are retained. --service selects images; --resume reuses raw reports only when filesystem layers and runtime configuration match, retaining original scan dates.

Report reference

Files under examples/sandbox/Contents

results_published_hardening.jsonEffective runtime user, filesystem and isolation assertions.

results_published_owasp*.json, results_published_outages.json, results_published_npm_audits.jsonReference/TLS outcomes, isolated failures and npm audits.
results_published_image_advisories.json, results_owasp_scan_*.jsonImage finding summaries and raw package-location evidence.
results_published_owasp_summary.mdCategory totals, failed image checks, remaining scope and grouped high/critical findings.

With --prefix published, the report renderer reads the results_published_* files together; it does not reconcile timestamps or package provenance for every component. Generate fresh components before treating an aggregate as current. Reports are ignored by Git and excluded from build images.

Assessment statuses mean pass: the specific assertion holds; fail: an assertion or advisory policy is violated; error: the check could not complete; not_assessed: no conclusion for the control. Failures/errors cause exit 1. A clean npm audit can coexist with OS image advisories. OWASP scope explains the remaining work.
