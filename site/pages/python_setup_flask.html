Current release: this page documents Python 1.1.8 and Rust/Python 0.2.7, both published on PyPI. Python 1.1.8 requires aiwaf-rust>=0.2.7; framework dependencies remain extras.

This guide retains the legacy integration steps. Use the native adapter example for the Rust-owned CSV pipeline.

How AIWAF works: system architecture

Add AIWAF to a Flask application and verify that protection is registered with the live route table.

Before you begin

Use an environment compatible with your framework. This guide assumes a Python application file named app.py. New to middleware? Start with the six-step first protected app tutorial, which includes complete files and expected responses.

1. Install the framework extra

pip install "aiwaf[flask]"
# Python 1.1.8 installs its required Rust runtime automatically.

Install into the environment used to run your application. Choose an interpreter compatible with the framework and dependencies.

2. Register protection

app.py

from flask import Flask
from aiwaf.flask import AIWAF

app = Flask(__name__)
AIWAF(
    app,
    middlewares=["auto"],
)

@app.get("/")
def home():
    return {"protected": True}

middlewares=["all"] enables the canonical middleware set. auto starts from the same set and omits checks that are not useful for the detected application signals.

3. Discover your live routes

Run from the application checkout after all routes are registered:

aiwaf init --framework flask --app app:app

For a file named app.py containing app = Flask(__name__), use --app app:app, not --app app.py. The first part is the Python module name without .py; the second is the application object. Run the command from the directory containing app.py. The CLI imports your application, so its dependencies and configuration must be available.

The default output is .aiwaf/paths.json. Flask and FastAPI require module:object in --app; Flask factories such as app:create_app are supported. Repeat discovery when registered routes change.

4. Scope route exemptions

Django, Flask, and FastAPI expose equivalent route helpers:

from aiwaf.flask import (
    aiwaf_exempt,
    aiwaf_exempt_from,
    aiwaf_only,
    aiwaf_require_protection,
)

@app.get("/health")
@aiwaf_exempt
def health():
    return {"ok": True}

@app.post("/webhook")
@aiwaf_only("header_validation")
def webhook():
    return {"accepted": True}

Canonical middleware names include header_validation, rate_limit, ip_keyword_block, honeypot, geo_block, uuid_tamper, ai_anomaly, and logging.

5. Configure settings and model storage

Set flat AIWAF_* values in app.config before calling AIWAF(app). Flask's constructor selects middleware; it does not accept FastAPI's nested option dictionaries.

When aiwaf_rust is importable, supported acceleration paths are selected automatically. Python remains the fallback when a native capability is unavailable. Persisted runtime models use JSON state; AIWAF does not load pickle, joblib, or other executable Python-object formats.

6. Start and verify

python -m flask --app app:app run --port 5000

Open http://127.0.0.1:5000/ in a browser. The handler should return {"protected": true}. Also test a deliberately rejected request on a non-exempt route; success alone does not prove enforcement. For exact three-success/one-throttle behavior, use the tutorial's controlled rate-limit test.

aiwaf flask --help
aiwaf flask train --help
aiwaf flask model --help

Use Python operations for training, model inspection, and state migration. Training requires representative logs in a supported format; setup alone does not train a model.

Production configuration

  • Configure the application to trust forwarding headers only from known proxy CIDRs.
  • Configure the outermost proxy to overwrite client-supplied forwarding headers.
  • Use Redis, a database, or another shared backend when multiple workers must share rate-limit, blocklist, or exemption state.
  • Keep health checks, static assets, and trusted webhook routes explicitly scoped instead of disabling protection globally.
  • Tune anomaly detection with representative normal traffic before relying on it in production.
  • Rotate logs and exclude secrets, authorization headers, cookies, and personal data.
  • Sign model/configuration artifacts where the runtime supports HMAC verification.
  • Run AIWAF alongside normal secure-development controls and an edge/reverse-proxy layer.

Rust-owned CSV request pipeline

Current release: this page documents Python 1.1.8 and Rust/Python 0.2.7, both published on PyPI. Python 1.1.8 requires aiwaf-rust>=0.2.7; framework dependencies remain extras.

Install the explicit native adapter instead of the existing AIWAF middleware chain. Installing the required Rust dependency does not automatically switch existing applications to this pipeline. Legacy adapters remain available for custom stores and hooks; their configuration and fallback behavior are separate.

from flask import Flask
from aiwaf.flask import NativeAIWAF

app = Flask(__name__)
aiwaf = NativeAIWAF(app, config={"data_dir": "aiwaf_data"})

The earlier setup steps on this page describe the legacy adapter. For native mode, replace that initialization with the example here and configure the dedicated lowercase profile. Do not install both chains. For authenticated form-timing exemptions, pass a synchronous authenticated(request) callback. A synchronous country_lookup(ip) callback is also supported; the default uses the bundled GeoIP lookup.

Rust owns the native CSV pipeline configuration, enforcement order, SQL and keyword inspection, geo/blocklist decisions, rate buckets, form timing, UUID scores, anomaly history/inference, keyword learning, and CSV logging. Python supplies framework routes, authentication facts, GeoIP lookup, bounded request buffering, and response construction. Training and management still have Python interfaces.
