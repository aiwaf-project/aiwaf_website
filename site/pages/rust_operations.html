How AIWAF works: system architecture

Proposing Rust changes

Every change under rust/ needs tests at each layer it touches, run against a build of your branch. Rust tests prove the logic is right; Python and WASM tests prove callers can use it.

Required tests

If your change affectsAddWhere
Logic that doesn't depend on PythonRust unit tests, including edge casesrust/crates/aiwaf_core/src/ or a #[cfg(test)] module in rust/src/
A function or class exposed to PythonA normal call, a bad input and one boundary edge caserust/tests/test_binding_boundary.py
A function exposed to WebAssemblyA binding testrust/crates/aiwaf_wasm/tests/wasm_api.rs
Behavior that exists in both Python and RustA parity test, with both languages changed in the same pull requestrust/tests/test_python_parity.py

A new export fails the binding suite until a test names it. A parser change made in only one language fails the parity tests.

Design rules

  • Put logic where it can be shared. Prefer aiwaf_core, which both the Python and WASM packages use. Keep PyO3 functions in rust/src/ focused on converting values.
  • Test your branch, not a published package. Tests must never run against aiwaf-rust from PyPI. The test runner and CI build it from rust/ and fail if the installed copy came from anywhere else.
  • Start bug fixes with a failing test. It should fail on the old code and pass with the fix.
  • Don't lock in known bugs. If a test exposes a bug you aren't fixing, mark it xfail(strict=True) with a reason, so it fails as soon as someone fixes the bug. Don't assert the wrong behavior.

Before opening a pull request

Run these from the monorepo root in a virtual environment. The runner rebuilds aiwaf-rust first.

cargo test --manifest-path rust/Cargo.toml --locked -p aiwaf_core
cargo test --manifest-path rust/Cargo.toml --locked -p aiwaf_rust --lib
cargo test --manifest-path rust/Cargo.toml --locked -p aiwaf-wasm --lib
python aiwaf_test.py --python-only
python -m pytest rust/tests -q
(cd rust/crates/aiwaf_wasm && wasm-pack test --node)

What CI runs

WorkflowRuns whenChecks
rust-tests.ymlRust, Python package or test files changeRust and WASM tests, then Python bindings and adapters against a source build
test.ymlPython, Node.js, Rust or test files changeThe full monorepo suite against a source build of aiwaf-rust

Workflows for a first-time contributor can wait for a maintainer to approve them.

Pull request checklist

  • Tests are added for every layer in the table above, and all of the commands above pass.
  • The description explains what changed, and whether it changes behavior for Python or Node.js users.
  • The description says whether a new aiwaf-rust or aiwaf-wasm release is needed, and whether the minimum version in the Python or Node.js package must go up.
  • CHANGELOG.md is updated for changes users can notice.

Publish aiwaf-rust before any Python release that requires the new version. Python release tests use a source build, so they don't prove that version is on PyPI.

Native Python build

Run these commands in a virtual environment from the monorepo root. The first command copies the shared README and license files into rust/, on any operating system. The copies are ignored by Git.

python scripts/stage_rust_package_files.py
python -m pip install maturin
maturin develop --release --locked --manifest-path rust/Cargo.toml
python -m pip install pytest
python -m pytest rust/tests -q

python aiwaf_test.py runs the same build for you before Python tests. Run it manually only when you use pytest or manage.py test directly.

Rust core and WASM

cargo test --manifest-path rust/Cargo.toml --locked -p aiwaf_core
cargo test --manifest-path rust/Cargo.toml --locked -p aiwaf_rust --lib
cargo test --manifest-path rust/Cargo.toml --locked -p aiwaf-wasm --lib
cd rust/crates/aiwaf_wasm
wasm-pack test --node
wasm-pack build --release --target bundler
cd ../..
python scripts/patch_wasm_pkg.py
cp ../LICENSE crates/aiwaf_wasm/pkg/LICENSE
cp ../NOTICE crates/aiwaf_wasm/pkg/NOTICE
cp -R ../licenses crates/aiwaf_wasm/pkg/

The metadata script also stages LICENSE, NOTICE, and licenses/. The explicit copy commands above produce the same assets. PowerShell can use Copy-Item for files and Copy-Item -Recurse for directories. Browser applications require a bundler that understands WebAssembly assets; initialize the WASM module before calling its exports.

Release manifests

The published Rust/Python version is 0.2.7; WASM is 0.2.5. They use independent releases under ELv2.

  • PyPI: rust/pyproject.toml and rust/Cargo.toml, rust-v0.2.7, rust-publish.yml.
  • npm: rust/crates/aiwaf_wasm/Cargo.toml, wasm-v0.2.5, wasm-publish.yml.
  • PyO3 uses ABI3 wheels for Python 3.8 and newer, exporting aiwaf_rust.

Verification

Confirm import aiwaf_rust works in the interpreter used by the application. Validate model round trips through fit, to_json, from_json, and predict. Python selects available Rust capabilities automatically and falls back when unavailable. WASM performance depends on batch size and conversion cost.

CSV validation and performance

# From the monorepo root, with the matching installed extension:
python scripts/check_native_csv_runtime.py
python scripts/check_csv_release_concurrency.py
python scripts/benchmark_native_training_boundary.py
python scripts/benchmark_native_csv_training.py
python scripts/benchmark_native_csv_workloads.py
python scripts/benchmark_csv_request_reuse.py
python scripts/profile_csv_logging.py

The preflight checks module locations, enabled flags, required capabilities, and temporary-file round trips without touching application data. Native snapshot caching and cached log handles are bounded. Closing writers matters before Windows log-directory deletion.

Three alternating runs on 10,000 synthetic records measured Apache timestamp speedups of 4.57x on Windows and 3.65x on WSL. Retained features plus a 20-tree Rust fit/predict boundary measured 1.55x and 1.35x. Native ISO parsing was slower on both, so it remains optional. An offline Windows Flask IP/keyword + CSV logging workload measured 5.95 ms native versus 9.18 ms Python. These are scoped measurements, not deployed throughput or complete training speedups.

Release validation includes quoting/gzip, timestamp fallback, seeded model parity, chunk equivalence, concurrent mutations, no-op writes, rotation/truncation, and writer reopening. The Linux four-process smoke check retained 160 log rows and 80 blocklist entries. Production load and the full platform/framework matrix still require deployment-specific checks.

Publish the Rust dependency before Python releases requiring it. Python release CI builds the matching extension from the repository for tests, so confirm the required version is on PyPI before tagging a Python release. Local test builds stay separate from Python release artifacts.

Native pipeline release and validation

Current release: this page documents Python 1.1.8 and Rust/Python 0.2.7, both published on PyPI. Python 1.1.8 requires aiwaf-rust>=0.2.7; framework dependencies remain extras.

Build/test NativeCSVPipeline and NativePipelineRequest in the installed wheel, not just the source extension. Run rust/tests/test_python_api.py and rust/tests/test_csv_pipeline_api.py. Publish the native wheels before the Python package that requires them.
