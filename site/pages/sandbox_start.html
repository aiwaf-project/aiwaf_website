Tutorial

Your first sandbox run

{% include _docs_source.html %}

Start with Juice Shop, Redis and Express, test one endpoint, then expand to fifteen published-package integrations. Run every command from the sandbox repository root.

1. Check requirements

  • Docker Desktop using Linux containers, or Docker Engine with Linux containers and Docker Compose.
  • Git, Python 3.10+, and network access to clone the repository and download packages/images.
  • Host Node.js 22 and npm only for JavaScript unit tests outside Docker.
  • Time and disk space for Node, Python, Java, and R image builds.
docker version
docker compose version
git --version
python --version

2. Clone the sandbox

git clone https://github.com/aiwaf-project/sandbox.git
cd sandbox
python -m pip install requests

Run all following commands from the repository root unless a block changes directory. Use python3 if that is your interpreter name. Runtime images install published packages; no host AIWAF, Java, Maven or PHP installation is needed.

3. Start one protected endpoint

docker compose build aiwaf
docker compose up -d aiwaf
docker compose ps

Build Express first because the one-shot log initializer uses its sandbox-aiwaf image. Compose starts Redis and Juice Shop dependencies. The initializer exiting with code 0 is expected; wait for the upstream services to be healthy.

Checkpoint: Direct Juice Shop is at http://127.0.0.1:3001; Express protection is at http://127.0.0.1:3000. Both bind only to loopback. Run the targeted checks below before expanding to all runtimes.

4. Test a protected endpoint

python examples/sandbox/smoke-test.py --target node=http://127.0.0.1:3000 --burst-workers 16 --output examples/sandbox/results_first_smoke.json
python examples/sandbox/validate-login-bypass.py --target node=http://127.0.0.1:3000 --output examples/sandbox/results_first_login.json

The smoke check requires normal requests to succeed, automation and excess traffic to be denied, and benign invalid credentials to reach Juice Shop as a 401. The SQL check requires two payloads to fail to obtain an authentication token; token values are omitted from reports.

Continue with full validation. If a check fails, inspect docker compose logs --tail 100 aiwaf and troubleshooting.

5. Expand and verify published packages

When ready for the full matrix, start all fifteen non-PHP integrations:

docker compose up -d --build aiwaf aiwaf_fastify aiwaf_hapi aiwaf_koa aiwaf_nest aiwaf_next aiwaf_adonis aiwaf_sails aiwaf-django aiwaf-flask aiwaf-fastapi aiwaf-java aiwaf-spring aiwaf-java-r aiwaf-spring-r
python examples/sandbox/run-published-packages.py --verify-only

The verifier compares installed versions with package-versions.json, checks registry installation details and records image IDs in results_published_versions.json. It requires all fifteen containers. Rebuild and recreate stale containers; restarting alone does not install new packages.

Without a service selection, docker compose up -d --build also starts the three PHP examples. PHP is outside this published-package validation scope.
