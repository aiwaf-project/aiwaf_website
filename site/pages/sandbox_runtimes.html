State ownership and persistence

Redis 7 uses AOF persistence in redis_data, has no published host port, and must pass its health check before protected services start. Services isolate state by database and key prefix. Java integrations share DB 14 with separate sandbox:java:, sandbox:spring:, sandbox:java-r:, and sandbox:spring-r: storage prefixes.

  • JavaScript uses rate-limit lists through the cache adapter.
  • Django uses its native Redis cache for rate limits, honeypot and anomaly history; WATCH/MULTI updates preserve serialized buckets across concurrent writers.
  • Flask/FastAPI use a shared rate-limit cache.
  • Java stores engine state, reputation and distributed counters.
  • PHP uses the Redis extension and RedisAdapter for rate counters.

Python/JavaScript model and blocklist storage retains supported adapter backends. A Redis rate cache does not move all state into Redis. Workers of one service must share its namespace for an aggregate budget. Startup clearing is disabled; rate keys expire and restarts preserve state.

JavaScript retains compatibility with legacy cache configurations. Closed mode rejects failed operations on the selected cache; it does not establish that every adapter configuration selects Redis. Flask invalid backend setup fails initialization; FastAPI invalid runtime cache configuration is rejected. Shared JavaScript upstream connection failures return generic 502 bad_gateway. Package versions and configuration

The inventory is examples/sandbox/package-versions.json: PyPI AIWAF 1.1.8 and aiwaf-rust 0.2.7; npm AIWAF 1.1.5 and aiwaf-wasm 0.2.5; Maven io.github.aiwaf-project:aiwaf-java 1.3.5. Verify installed packages with run-published-packages.py --verify-only. Editing the inventory alone does not change Docker installations.

Node imports aiwaf. Plain Java reads /app/aiwaf.json with environment overrides and supports AIWAF_CONFIG_FILE. Spring uses Boot auto-configuration and route discovery. Its sandbox forwarded-IP trust covers 172.16.0.0/12; change AIWAF_SANDBOX_TRUSTED_PROXY_CIDRS to the actual proxy CIDRs elsewhere.

Compose enables synthetic client traffic and runtime-specific debug/logging settings and disables or raises thresholds for some learning paths. These are evaluation policies, not production defaults or proof that every AI/accelerator path is exercised. Review the selected service environment before interpreting results.

Build and runtime hardening

  • Node uses npm ci, a compiler build stage and a digest-pinned Node 22 runtime. Serving images remove npm/npx/Yarn and start Node directly. Audits use a separate tools image.
  • Python uses digest-pinned bases and Linux x86_64 / CPython 3.11 wheel hash locks. Java builds use Maven properties and explicit security dependency overrides. Review each Dockerfile and lock when upgrading.
  • The fifteen non-PHP serving runtimes run as UID/GID 10001 with read-only roots, all capabilities dropped and privilege escalation disabled. Writable paths are temporary /tmp//state, the shared log volume, and Next's build cache.
  • /state, including Django's demo SQLite database, is ephemeral. Redis and logs retain their named-volume lifetimes. The one-shot initializer runs as root with CHOWN/DAC_OVERRIDE to prepare log ownership.
  • Java images remove the unused pebble executable. Build-time distribution updates do not establish that every OS advisory is fixed.
  • Redis, Juice Shop, PHP and reference fixtures have separate security configurations; do not extend the fifteen-runtime hardening claim to them.

Tool caches, exported TLS material and generated reports are excluded from build contexts. Input pinning is not signed provenance, a full SBOM or proof of identical output. Run current audits and triage their findings.
