How AIWAF works: system architecture

Unified CLI

# Bare help selects the single installed framework
aiwaf --help

# Explicit Flask policy commands
aiwaf flask blacklist migrate
aiwaf flask status

# Django management commands
python manage.py detect_and_train
python manage.py regenerate_model
python manage.py aiwaf_reset --keywords --confirm
python manage.py aiwaf_logging --status
python manage.py geo_block_country list

# Explicit adapter dispatch
aiwaf django aiwaf_list --all
aiwaf flask --help
aiwaf fastapi --help

Bare commands select the single installed supported framework. When several frameworks are installed, use an explicit prefix: aiwaf flask ..., aiwaf fastapi ..., or aiwaf django <management-command> .... fast remains a FastAPI alias. aiwaf init accepts --framework and --app for route discovery; these flags do not choose the adapter for bare commands. FastAPI training has its own --app option. Django uses its management-command names; bare status is not a Django management command.

Blacklist migration

Version 1.0.7 introduced weighted reputation, progressively longer temporary blocks, expiration, and richer blacklist metadata. Existing blacklist data has compatibility handling; aiwaf blacklist migrate performs backend-aware migration. Legacy CSV schemas are detected and imported permanent blocks are converted safely. Review existing entries and back up runtime state before migration.

Model storage

Persisted Python models use JSON state. Pickle, joblib, and executable Python-object formats are unsupported. Regenerate old model artifacts through the current trainer. Python 1.1.6 installs its required aiwaf-rust>=0.2.5 dependency. Legacy adapters select supported native operations while retaining their compatibility paths; the complete native pipeline requires an explicit adapter and has no Python policy fallback.

Deployment

  • Configure the application to trust forwarding headers only from known proxy CIDRs.
  • Configure the outermost proxy to overwrite client-supplied forwarding headers.
  • Use Redis, a database, or another shared backend when multiple workers must share rate-limit, blacklist, or exemption state.
  • Keep health checks, static assets, and trusted webhook routes explicitly scoped instead of disabling protection globally.
  • Start anomaly detection in observe-only or conservative mode and tune it with representative normal traffic.
  • Rotate logs and exclude secrets, authorization headers, cookies, and personal data.
  • Sign model/configuration artifacts where the runtime supports HMAC verification.
  • Run AIWAF alongside normal secure-development controls and an edge/reverse-proxy layer.

Rust-backed CSV operations and training

Python 1.1.6 requires aiwaf-rust>=0.2.5 as a base dependency. Framework extras select Django, Flask or FastAPI. The optional rust extra remains an installation alias. Legacy capability selection is automatic unless disabled; the new complete pipeline requires the explicit adapter.

pip install "aiwaf[flask,rust]"
# Run these repository scripts with the matching installed packages.
python scripts/check_native_csv_runtime.py
python scripts/check_csv_release_concurrency.py

# FastAPI: import the live application and use its routes/runtime stores.
aiwaf fastapi train --app app:app --log-dir aiwaf_logs --disable-ai
aiwaf fastapi train --app app:app --log-dir aiwaf_logs --model-path model.json
# Django retains its management-command workflow.
python manage.py detect_and_train

FastAPI also exposes aiwaf.fast.trainer.train_from_logs(app, ...). --data-dir selects the shared policy CSV directory and imports an existing legacy runtime_store.csv once. Training writes shared keyword and blacklist files; keyword frequencies are retained in auxiliary runtime metadata. AI training obeys its volume threshold; --force-ai explicitly overrides that threshold. Training optionally writes a JSON model artifact. Reload the model explicitly or restart the application: existing FastAPI anomaly middleware instances do not automatically adopt the new forest.

Flask, Django CSV, and FastAPI stream plain/gzip CSV directly in bounded batches, including quoted newlines and seconds/milliseconds timing fields. Supported Apache logs use batched extraction and timestamp parsing. Django preserves its legacy CSV timezone/microsecond truncation; Flask and FastAPI preserve ISO offsets. Unique route checks, per-IP aggregation, and keyword persistence are batched. Native feature handles keep the matrix, forest fitting/prediction, and anomaly statistics in Rust, without a Pandas DataFrame. Custom parsers, missing capabilities, and Unicode keyword learning retain compatibility paths.

CSV access logs are written and flushed synchronously under OS locks. Cached writer handles detect rotation, replacement, and truncation. After requests stop, call the Flask logger's close() or aiwaf.core.native_runtime.close_csv_logs() before deleting temporary directories, especially on Windows. Handles also close at process shutdown. AIWAF_CSV_LOG_FSYNC=True adds per-row disk sync; without it, a system crash can lose recently flushed OS-buffered entries. There is no application-side logging queue.

Native pipeline performance and deployment

Release candidate: this page documents Python 1.1.6 and Rust/Python 0.2.5 in the current source checkout. Source versions do not establish registry availability. Python 1.1.6 requires aiwaf-rust>=0.2.5; framework dependencies remain extras.

Matched WSL Linux measurements used all eight stages, immediate CSV logging, 1,000 blacklist entries, 80% GET / 20% JSON POST (30 fields), and one concurrent client. Three alternating 300-request runs per framework/mode used a seeded 100-tree Rust forest and 200 initial history records per client when AI was enabled. GeoIP reflects a local fixture.

Model and worker lifecycle

Pass a trained Rust IsolationForest as model=, or use Django's AIWAF_CSV_PIPELINE_MODEL. Load a new snapshot with pipeline.native.set_model(model) where you hold the engine reference, or reload workers. Native initialization does not automatically train or load the legacy adapter's model artifact. The runtime's diagnostics() reports model activation and state counts.

Release order

Publish aiwaf-rust 0.2.5 before aiwaf 1.1.6. Native wheels target Linux x86_64/aarch64, musl x86_64, macOS x86_64/arm64 and Windows x86_64. Windows and WSL builds were checked locally; all remaining wheel targets must pass release CI. Local validation passed eight test groups and ten independent Windows native API smoke checks. These local checks do not replace platform CI.

Python 1.1.4 CSV migration checks (historical)

This source release adds installed-framework CLI detection, the explicit fastapi alias, reuse of existing Flask data directories, and shared policy CSV startup migration. It keeps aiwaf-rust>=0.2.3; these changes require no new native API.

# Show the deployed interpreter's installed versions.
python -m pip show aiwaf aiwaf-rust
python -c "import aiwaf; print(aiwaf.__version__)"

# Flask-style policy management can inspect the shared policy directory.
aiwaf flask --data-dir /absolute/path/aiwaf_data status

# Route-aware FastAPI training uses the same policy directory.
aiwaf fastapi --data-dir /absolute/path/aiwaf_data train --app app:app --log-dir aiwaf_logs --disable-ai

Stop older workers before importing legacy CSV data. Original sources, pre-import backups, and completion markers remain on disk. Correct invalid legacy input and restart to retry an incomplete migration; subsequent writes to a completed legacy source are not replayed. Use the same directory for application, training, and management commands.

Local validation passed a broad 869-test core/Flask/FastAPI run, 284 tests through Django's test runner, and focused migration/UTF-8 compatibility checks. The 1.1.4 wheel and source archive were built and the packaged version, CSV backend, and required Rust dependency were verified. Source artifacts do not establish that a registry release has been published.
