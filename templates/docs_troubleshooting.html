Troubleshooting and Verification

{% include '_docs_source.html' %}

CLI rejects --app app.py

--app takes a Python import target, not a filename. For app.py containing app = Flask(__name__), run from its directory:

aiwaf init --framework flask --app app:app

For a factory use app:create_app. For Django use --framework django --settings project.settings. Install dependencies and load the application's configuration in the same environment; discovery imports the live application.

Manifest has only / and static routes

Confirm the imported file is your intended application, all blueprints/routers are registered, and the app factory finishes before discovery:

python -c "import app; print(app.__file__); print(*sorted(r.rule for r in app.app.url_map.iter_rules()), sep='\n')"

This diagnostic is for a Flask module-level app. Regenerate the manifest after registering additional routes. An unimported blueprint cannot appear in the live route table.

Website setup page returns 404 or 500

/docs/python/setup redirects to /docs/python/setup/django. /python/setup/django redirects to the same canonical guide. Both app runners register the shared documentation blueprint. Unknown pages return 404; errors inside an existing template remain server errors.

  1. Check which checkout the WSGI worker imports and which entrypoint the host uses.
  2. Deploy documentation.py and all templates together, including shared includes.
  3. Reload the host's web application or restart workers after updating source/dependencies.
  4. Read the server traceback for import errors, missing includes, or initialization failures. A 500 page alone does not identify the cause.
python -m unittest discover -s tests -v
python -c "from wsgi import application; print(application.url_map)"
curl -i https://aiwaf.org/health

The import check initializes the actual website and may create runtime files. Tests isolate documentation routing and rendering; a passing test does not establish that the deployed worker has reloaded. /health is liveness, not database/cache readiness.

Normal traffic is blocked, or test traffic is never blocked

Compare response details and logs with the selected middleware, route plan, client IP, headers, and block/reputation state. A 403 may come from AIWAF or a proxy; avoid attributing it without evidence. Rate throttling can have different status semantics from a deterministic block.

Private clients, health paths, static paths, or route annotations may be exempt. Local curl success alone does not demonstrate protection for public clients. To exercise header validation, use a non-exempt route and a client context matching deployment; include representative User-Agent/Accept headers and browser-standard headers such as Accept-Language/Accept-Encoding in the normal case. Plain curl requests can be rejected by the website's header policy; use a browser or matching headers to check protected documentation. The website explicitly exempts /health for liveness probes. Configure a small staging threshold and test below, at, and above the boundary. Do not disable protection globally to resolve a single route.

Client IP or multi-worker counters look wrong

Inspect address extraction for your adapter and the actual forwarding-header chain. Have the trusted outer proxy overwrite client-supplied headers. Java has explicit trusted proxy CIDRs; Python/Node resolution follows their own rules.

File persistence is separate from a shared rate cache. Redis configuration must resolve to an active shared backend. In Flask, Redis initialization can fall back to memory; test enforcement across two workers and examine initialization logs. Use the same rate-key prefix for workers sharing one service, and distinct prefixes for unrelated services.

Training produces no usable model

Verify that the trainer reads the actual log path/format, logs include response observations, minimum sample thresholds are met, and the output model is written where runtime inference loads it. Representative normal traffic is needed; forced training does not repair missing or malformed inputs. Inspect trainer/model help for the installed adapter:

aiwaf flask train --help
aiwaf flask model --help
# Django uses its management commands:
python manage.py detect_and_train --help

Python requires JSON model state. Regenerate legacy executable artifacts rather than renaming their extension. Verify model load diagnostics after deployment/reload. Models with different feature schemas or native formats need a supported conversion path or retraining.

Verification before publishing documentation

Render every page; check internal links, fragment anchors, setup redirects, and unknown-page behavior. Then test code samples with the installed runtime in a clean staging environment, including a normal request and an intentional rejection. Finally test the public URLs after deployment. These are separate checks.
