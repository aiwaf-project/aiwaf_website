Read logs and plan training

{% include '_docs_source.html' %}

Enforcement decisions are easier to operate when you can connect them to request observations. The tutorial already selects logging; now inspect the files it writes and understand the boundary between logging and training.

1. Read the access log

From the app directory:

python -c "from pathlib import Path; print(Path('aiwaf_logs/access.log').read_text())"

AIWAF_LOG_FORMAT='json' writes JSON records to the access log. Look for the request path and response status for the message/preview calls. Timestamps, durations, addresses, and record details depend on the runtime; the file is evidence of the observed requests, not a trained model.

2. Separate three kinds of state

DataPurposeTutorial behavior
Rate countersDecide whether the current request crosses the windowIn memory in this process; lost on restart
Request logs / CSV stateRecord observations and persist store data when usedFiles under the configured directories
Model artifactScore behavior after offline trainingNo anomaly model is trained or selected here

Keeping CSV files does not make rate counters shared across workers. See shared state configuration before scaling beyond a single process.

3. Inspect the trainer before running it

aiwaf flask train --help
aiwaf flask model --help

For an application with a representative combined-format log corpus, the Flask trainer accepts:

aiwaf flask train --log-dir /path/to/combined-format-logs

This is a separate operational example, not the next command to run on these few JSON tutorial records. Check the installed trainer's supported input formats, volume thresholds, output path, and model diagnostics. Convert or collect a supported log format deliberately; do not assume the logger format is the trainer format.

Current Python persisted models use JSON. A file with a different extension does not become a compatible model by renaming it. Collect representative traffic, train with the runtime's supported workflow, and verify model loading before enabling anomaly inference. Logs can contain request data; configure retention and redaction for your application.
