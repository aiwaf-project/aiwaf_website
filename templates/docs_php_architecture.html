Core Design

AIWAF-PHP Architecture Deep Dive

1-4. Purpose, Snapshot, Structure, Architecture

  • Package: aayushgauba/aiwaf, Composer library, PHP >=7.4.
  • Primary runtime entry: AIWAF::protect(); training entry: cli/detect_and_train.php.
  • Top-level focus: src/, src/Core/, src/Adapters/, src/RateLimit/, resources/, tests/.
  • Design traits: defense-in-depth, exemption-first, conservative AI guardrails, flexible persistence backends.

5. Runtime Entry And Integration Surface

Primary API (src/AIWAF.php)

  • AIWAF::protect() executes per-request security controls.
  • AIWAF::setPathExistsResolver() enables route-awareness for framework integrations.
  • AIWAF::setMiddlewareDecisionResolver() supports custom middleware gating logic.
  • AIWAF::getLastTrainingTelemetry() exposes latest trainer telemetry snapshot.

Typical Bootstrap

  • Load Composer autoload.
  • Initialize selected rate-limit adapter.
  • Call AIWAF::protect() early in front-controller lifecycle.

6. Request Protection Flow (AIWAF::protect)

  1. Build runtime config via Config::toRuntimeConfig().
  2. Resolve request identity (ip, path).
  3. Exemption short-circuit.
  4. Header validation.
  5. Blocked-IP enforcement.
  6. Geo policy checks.
  7. AI anomaly scoring (model + threshold gated).
  8. Rate-limit enforcement (429, optional block persist).
  9. Dynamic keyword checks.
  10. UUID tamper checks.
  11. Honeypot checks.

Block responses use 403 for deny cases and 429 for rate-limit violations.

7. Core Modules Responsibility Map

src/

  • AIWAF.php, Config.php, Utils.php
  • RateLimiter.php, IPBlocker.php
  • DynamicKeywordManager.php, UUIDTamperProtector.php, HoneypotChecker.php
  • FeatureExtractor.php, IsolationForest.php, Logger.php

src/Core/

  • RuntimeConfig.php, HeaderValidation.php, GeoIP.php, Exemptions.php
  • Logs.php, Training.php, TrainingLogic.php
  • StorageOps.php, StorageCsvImpl.php, StorageSchema.php, BlacklistManager.php

Rate-Limit Layers

  • Adapters in src/Adapters/ bridge runtime usage.
  • Drivers in src/RateLimit/ provide backend-specific persistence behavior.

8-9. Storage, Artifacts, Training Lifecycle

Artifacts (default under resources/)

  • blocked_ips.json, dynamic_keywords.json, request_features.csv, forest_model.json.
  • php setup.php ensures required baseline files exist.

Training Pipeline (AIWAF::detectAndTrain)

  • Entry: php cli/detect_and_train.php.
  • Primary source: AIWAF_ACCESS_LOG, including rotated log handling.
  • Controls: min log thresholds, force/disable flags, anomaly threshold, known paths.
  • Outputs: model updates, dynamic keyword updates, optional anomaly-driven block updates, telemetry.

Telemetry Includes

  • line counts, parse failures, feature rows
  • keyword candidate/learned counts
  • anomalous/blocked IP totals and top-country summaries
