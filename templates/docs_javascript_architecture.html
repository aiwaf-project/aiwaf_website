Core Design

Architecture And Runtime Flow

High-Level Architecture

  • Unified core pipeline in lib/wafMiddleware.js.
  • Defense-domain modules in lib/ (rate, headers, geo, anomaly, keyword, UUID, honeypot).
  • Storage managers prefer SQLite and fail open to CSV when DB is unavailable.
  • Training pipeline learns from logs and runtime data stores.
  • Non-Express adapters normalize into Express-like req/res/next contract.

Runtime Entry And Framework Adapters

Package Entry (index.js)

  • Default export: Express-compatible middleware.
  • Named targets: Fastify, Hapi, Koa, Nest, Next.js, Adonis.
  • Sails alias points to Express middleware path.

Adapter Behavior

  • Fastify: onRequest hook with wrapped status/json/send response helpers.
  • Hapi: server.ext('onRequest') and takeover response mapping on deny.
  • Koa: wraps ctx with Express-like methods, forwards only if not handled.
  • Nest: middleware class delegates to core middleware in use(req,res,next).
  • Next.js: wrapper runs AIWAF first, blocks short-circuit, else calls original handler.
  • Adonis: maps context request/response into Express-like contract.

Core Request Pipeline (lib/wafMiddleware.js)

Initialization Phase

  • Settings normalized through normalizeSettings(rawOpts).
  • Defense modules initialized: rate limiter, keyword detectors, anomaly, header validation, geo, exemptions, logger, feature utils.
  • Optional startup clear via AIWAF_CLEAR_STATE_ON_START.

Per-Request Flow

  1. Resolve metadata (ip/path/method) and logger hooks.
  2. Optional method policy block (AIWAF_METHOD_POLICY_ENABLED).
  3. Exemption short-circuit (bypasses remaining checks if IP or path is exempt).
  4. Blocked IP check (early reject for known bad IPs).
  5. Header validation (enforces structural constraints and presence of required headers).
  6. WASM Validation Checks (if AIWAF_WASM_VALIDATION is enabled):
    • Headers: Evaluates header combinations against high-performance WASM rules.
    • URL: Inspects full URL topology and request context via WASM.
    • Content: Validates raw or JSON parsed request bodies (req.body).
    • Recent Behavior: Aggregates up to 200 recent requests for temporal WASM evaluation (AIWAF_WASM_VALIDATE_RECENT).
  7. Geo policy check (compares req IP against block/allow lists).
  8. Honeypot/timing checks (evaluates rapid form submissions against expected human interaction times).
  9. Rate limit record + block decision (checks both burst/flood patterns and steady-rate thresholds).
  10. Static and dynamic keyword checks (inspects path against known malicious strings and dynamically learned signatures).
  11. UUID tamper checks (detects probing or malformed UUID injections).
  12. Unknown-Route Anomaly Decision: Only runs if the path does not match a known framework route (e.g., Express router). Evaluates a 6-feature vector against a trained Isolation Forest model. If anomalous, cross-references recent behavior (last 5000 requests over 5 minutes) measuring 404 scanning, burst rates, and keyword hits before issuing a block.
  13. Response-finish keyword learning for suspicious 404 patterns (lazy learning step after response finishes).
  14. next() when not blocked.

Block Response Model

Responds with 403, 405, or 429. Automatically falls back to JSON responses if the client sends Accept: application/json, is an XHR request, or if forced via AIWAF_FORCE_JSON_ERRORS.

Detailed Middleware Execution Chain

The core lib/wafMiddleware.js executes the following defense layers sequentially. Order is strictly enforced to ensure fast-path exits (like exemptions) prevent unnecessary processing of heavier tasks (like ML scoring):

  1. Initialization & Hooks: Resolves request metadata (IP, path, method) and attaches the logger hook to the response finish event.
  2. Method Policy Block: Drops requests with unexpected verbs early if AIWAF_METHOD_POLICY_ENABLED is active.
  3. Exemption Short-Circuit: Evaluates IP and Path exemptions. Bypasses remaining checks if a match is found.
  4. Blocked IP Check: Rejects known bad IPs stored in the `blacklistManager`.
  5. Header Validation: Enforces structural constraints, verifies required headers, and drops bot-pattern signatures.
  6. WASM Validation Checks: (Optional) Evaluates high-performance WASM rules across Headers, full URL topology, Body content, and temporal behavior over the last 200 requests.
  7. Geo Policy Check: Evaluates the source IP against MMDB allow/block rules.
  8. Honeypot & Timing Checks: Defends against automated form abuse by comparing submission times against AIWAF_MIN_FORM_TIME and checking for expected user-agent delays.
  9. Rate Limit Check: Enforces burst and steady-state AIWAF_RATE_MAX windows via the rateLimiter backend.
  10. Keyword Checks (Static & Dynamic): Inspects the path against hardcoded signatures (e.g., .php, wp-admin) and dynamically learned strings from the dynamicKeywordStore.
  11. UUID Tamper Check: Evaluates the path for malformed UUID injections or UUID-specific 404 probing.
  12. Unknown-Route Anomaly Check: Only runs for unknown routes. Evaluates a 6-feature vector against the Isolation Forest model and cross-references recent temporal burst/404 scanning behaviors before blocking.
  13. Post-Response Learning: Triggers the dynamic keyword learning hook lazily after the response is sent to minimize latency.

AST Static Analysis (lib/sourceAst.js)

The AST layer extracts a deterministic route manifest during startup to selectively enforce rules without requiring runtime regex matching. It relies on bounded static source analysis when framework metadata is missing.

  • Parsing: Uses @babel/parser to parse route handlers via Function.prototype.toString.call(handler). It handles JSX, TypeScript, and modern JS syntax.
  • Traversal: Custom recursive traversal visits all nodes to build confidence scores (apiScore, formScore, authScore).
  • Method Inference: Inspects StringLiteral and BinaryExpression nodes against req.method to infer supported HTTP verbs.
  • API vs Form Scoring:
    • Increases apiScore when it encounters res.json(), res.send() with Object Literals, or checks for req.body.
    • Increases formScore when it finds res.render(), res.redirect(), or checks for req.form/req.file.
  • Auth Detection: Detects logout, authenticate, register, and token logic (e.g., jwt, bcrypt) from CallExpression and Identifier nodes to classify the endpoint as an authentication boundary.

Path Generation and Auto Middleware (lib/pathManifest.js)

The AST data is ingested into the Path Manifest builder, which intelligently categorizes routes and automatically auto-toggles specific middlewares.

  • Route Classification (classifyRoute): Routes are binned into categories like api, form, admin, upload, static, or auth based on AST signals and Framework router introspection (Express/Fastify/Next).
  • Auto Middleware Planning: The protections array is tailored to the route category. For instance:
    • API Endpoints: HTML honeypots are disabled, JSON payload checks are enforced, and rate limits are raised to 120 req/min.
    • Static Assets: CPU-heavy checks like ML anomaly scoring, honeypots, and header validations are automatically disabled on paths matching /static/ or .png.
  • Rule Compilation (compileManifestToPathRules): These categorized protections are natively compiled into DISABLE arrays and RATE_LIMIT override configurations that the wafMiddleware.js directly consumes on every request.

Storage And Persistence Strategy

  • SQLite via Knex in utils/db.js (:memory: in tests; ./aiwaf.sqlite otherwise).
  • Lazily-created tables include blocked/exemptions/geo/request logs/dynamic keywords/model artifacts.
  • On DB failure, stores switch to CSV fallback under logs/storage/.

Training And Learning Pipeline (train.js)

Source Priority

The training pipeline sequentially attempts to read requests from multiple sources, stopping at the first available populated source:

  1. Access logs (AIWAF_ACCESS_LOG/NODE_LOG_PATH + glob/rotated gzip files). Defaults to /var/log/nginx/access.log.
  2. Middleware JSONL logs (AIWAF_MIDDLEWARE_LOG_PATH).
  3. Middleware CSV logs (AIWAF_MIDDLEWARE_LOG_CSV_PATH).
  4. DB request logs (via requestLogStore.recent(20000)).

Pre-Training Abuse Checks

  • Exemptions: Clears known exempt IPs from the blacklist prior to evaluation.
  • 404 Probing: Blocks IPs that generate at least 6 non-login 404 requests (e.g., dirbusting) if the non-login 404s exceed the login 404s.

Controls And AI Training

  • Threshold gates: AIWAF_MIN_TRAIN_LOGS (default: 50), AIWAF_MIN_AI_LOGS (default: 10000), AIWAF_FORCE_AI_TRAINING.
  • Feature Vector (6 dimensions): Extracted per request for the Isolation Forest:
    1. Path length (pathLen).
    2. Keyword hits against static signatures (kwHits).
    3. Status bucket index (statusIdx mapping to 200, 403, 404, 500).
    4. Response time (respTime).
    5. Burst count (burst): requests from the same IP within a 10-second rolling window.
    6. Per-IP 404 count (total404).
  • Anomaly Evaluation: Fits the IsolationForest (100 trees, sample size 256). Identifies anomalous IPs (score > 0.5) and checks their behavior context. Blocks the IP only if it exceeds specific thresholds: average keyword hits ≥ 2, 404s ≥ 10, burst ≥ 15, or total requests ≥ 100. Saves the model to model.json with version metadata.

Keyword Learning

  • Control: AIWAF_ENABLE_KEYWORD_LEARNING (default: true).
  • Extracts path tokens > 3 characters from 4xx/5xx requests that match a malicious context.
  • Malicious Context Indicators: Includes path traversals (../), sensitive files (.env, wp-admin, passwd), command injection (shell, eval, cmd), XSS (%3c%73%63%72%69%70%74, <script), or excessive 404 path length/depth.
  • Excludes known static keywords and legitimate tokens (e.g., api, auth, login, plus any from 2xx/3xx requests in the logs).
  • Adds the top occurrences (capped by AIWAF_DYNAMIC_TOP_N, default 10) to the dynamicKeywordStore.
