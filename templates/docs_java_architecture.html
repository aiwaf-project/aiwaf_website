Core Design

Architecture And Shared Layer

High-Level Architecture

  • Request adaptation maps framework requests to AiwafRequest.
  • AiwafEngine.evaluate(...) executes controls in deterministic order.
  • Runtime state is handled through storage abstraction and typed stores.
  • Decision output is AiwafDecision allow/deny with status and reason.
  • Spring route-level middleware overlays can refine global policy.

Request Pipeline Order (AiwafEngine)

  1. Path-rule match and effective middleware computation.
  2. Path/IP exemption resolution.
  3. Blacklist gate and optional method allow-list.
  4. IP keyword and dynamic keyword checks.
  5. UUID tamper and honeypot timing checks.
  6. Header validation checks.
  7. Geo policy gate.
  8. Rate-limit/flood checks and optional blocklisting.
  9. Allow decision when all checks pass.

Core Package Map (com.aiwaf.core)

  • AiwafEngine, AiwafConfig, AiwafRequest, AiwafDecision
  • ServletRequestMapper for servlet request normalization
  • HeaderValidationCore, ExemptionsCore, RateLimitPolicyCore, GeoCore, GeoIpCore
  • HoneypotCore, UuidPolicyCore, ApiPolicyCore, BlockPolicyCore
  • CoreCli, ReplayCore, WhoisLookup

Runtime Storage Layer (com.aiwaf.runtime)

  • Facade: RuntimeStorage.initialize(backendType, filePath)
  • Backends: MemoryStorage, FileStorage, CsvStorage
  • Typed stores: exemptions, path exemptions, blacklist, keywords, geo blocks
  • BlacklistManager provides block/unblock/whitelist/statistics operations

Spring And Servlet Layers

Spring (com.aiwaf.spring)

  • AiwafFilter request enforcement
  • AiwafInterceptor route middleware decisions
  • Annotations: exempt, exempt-from, only, require-protection

Servlet (com.aiwaf.servlet)

  • AiwafServletFilter request adaptation and deny/allow response flow

GeoIP And External Tooling

  • GeoIpCore can call mmdblookup and cache availability status.
  • Bundled MMDB path helper: GeoIpCore.defaultMmdbPath().
  • AiwafConsole whois relies on WhoisLookup and external whois support.
