Adapter Deep Dive

Execution Model By Framework

Django (aiwaf.django)

Entry and Request Pipeline

  • Primary entry exposes middleware classes from aiwaf/django/middleware.py.
  • Pipeline evaluates exemptions/path rules first, then applies block logic, anomaly checks, and logging.
  • Trainer reads logs and RequestLog records to retrain model and dynamic keywords.

Storage and Model Options

  • models mode (ORM-backed stores) or csv mode.
  • Model artifact storage via file, db, or cache.

Flask (aiwaf.flask)

Execution Style

  • Hooks into before_request and after_request for middleware behavior.
  • Route-level gating via decorators like aiwaf_exempt, aiwaf_exempt_from, aiwaf_only.
  • Storage supports DB, CSV, and memory fallback modes.

Operational Parity

  • Flask CLI exposes training/list/reset/maintenance surface used by FastAPI shim as well.

FastAPI (aiwaf.fast)

Runtime Orchestrator

  • AIWAF alias points to core/runtime_fastapi.py orchestrator.
  • Initializes config, storage backend, middleware order, and lifespan behavior.

Middleware and Routing Controls

  • Uses Starlette BaseHTTPMiddleware classes for protection layers.
  • Decorator/path-rule gating from shared runtime decorators determines which middleware applies per route.
  • Uses shared runtime storage and blacklist managers directly.

Cross-Adapter Consistency Notes

  • All adapters share common detection/training/storage primitives from aiwaf/core.
  • Behavior may vary slightly by framework integration depth and storage mode semantics.
  • Exemption and path-rule systems are central for reducing false positives in all frameworks.
