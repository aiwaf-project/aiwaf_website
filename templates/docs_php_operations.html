AIWAF-PHP Operations

10. Operational Command Surface

php setup.php
php cli/detect_and_train.php
composer test
composer run cover-everything
composer run test-adapters-matrix
composer run validate-all

AIWAF-PHP operations are script-based (PHP/Composer), not a Node-style monolithic CLI.

11. Configuration Model

Layering

  1. Defaults in Core\RuntimeConfig
  2. Optional JSON file via RuntimeConfig::loadFromFile
  3. Environment mapping via RuntimeConfig::loadFromEnvironment
  4. Runtime overrides via RuntimeConfig::update

Static Config Highlights (Config)

  • Config::$exemptPaths, Config::$knownPaths
  • Config::$rateLimitPerMinute
  • Config::$keywordDetectionThreshold
  • Config::$uuidTamperThreshold
  • Config::$aiAnomalyThreshold
  • Config::HEADER_MIN_SCORE, Config::REQUIRED_HEADERS

Env Mapping Highlights

  • Storage, header validation, rate limiting, detection toggles, geo policies, blacklist/logging controls.

12. Request Lifecycle (Simplified)

  1. Request enters front controller/bootstrap.
  2. AIWAF::protect() evaluates exemptions and enabled controls.
  3. Failing controls block with 403/429 and may persist IP consequences.
  4. Passing requests continue to app routing.
  5. Training loop independently updates model and keywords from historical logs.

14. Packaging And Release Surface

  • Composer name: aayushgauba/aiwaf
  • PSR-4 namespace: AIWAF\\ -> src/
  • Dev namespace: AIWAF\\Tests\\ -> tests/
  • Archive excludes include /examples and /tools

15. Operational Notes

  • Run AIWAF::protect() early, before side effects/output.
  • Keep exemptions explicit for health checks and trusted callbacks.
  • Treat anomaly blocking as data-dependent and retrain with representative logs.
  • Select adapter/driver backend according to deployment topology and durability needs.
  • Validate thresholds/settings with staged traffic before tightening.
