Rust and WASM Architecture

Rust implements shared computation primitives. PyO3 and wasm-bindgen expose them to host applications, while the Python or JavaScript host retains responsibility for HTTP policy, storage, logging, and response handling.

How AIWAF works: system architecture

One core, two binding boundaries

  1. Host runtimeSelect the operation and provide normalized input.
  2. Binding conversionPyO3 or wasm-bindgen converts host values into Rust data.
  3. Shared Rust coreMatch, validate, extract features, analyze behavior, or score a forest.
  4. Host decisionConvert the result back and apply framework policy.
Source areaResponsibility

Matching without rebuilding work per request

KeywordMatcher escapes configured keywords into literal patterns and builds a regex set. first_match preserves configured keyword order. The host can reuse the matcher rather than rebuilding pattern machinery on each request.

RouteMatcher indexes normalized prefixes. Matching starts with the deepest candidate and walks parent path boundaries until it finds a stored prefix. Duplicate normalized prefixes retain their first configured index. The host still normalizes paths and interprets the matching rule's policy.

Record conversion and stateful feature extraction

Bindings convert request records into typed structures before the core computes features. Batched and incremental extraction share the computation layer; incremental calls carry explicit state so recent client activity is available across batches.

That extraction state is distinct from a framework's blacklist or distributed rate-limit store. Sending a batch to Rust does not automatically replicate application state across workers. The host chooses where records and extraction state live.

The feature order is part of the model contract. A trainer and scorer must agree on the order, status mapping, time units, and window semantics. Summary fields ending in _ms use milliseconds; the feature vector uses seconds. Sharing feature names alone does not make every model artifact interchangeable.

Inside the forest

Training samples rows and grows isolation trees with random feature selections and split points. Tree traversal measures the number of splits required to isolate a point; short average isolation paths indicate more unusual samples.

anomaly_score uses the direction where higher means more anomalous. score_samples uses the opposite, scikit-learn-aligned direction. decision_function subtracts the configured offset, and predict returns inlier or outlier labels. The host must use the matching threshold convention.

Ordinary fitting replaces the forest unless warm-start append is selected. Retraining supports the append lifecycle. Random seeds and sampling settings affect the trained state, so score comparisons should use compatible artifacts and settings.

JSON is the artifact boundary

The forest exports state through to_json and restores it through from_json. Tree structure, settings, and scoring state travel as data. The host decides whether to store that state in a file, database, or cache and checks feature and artifact compatibility when loading.

Python's Rust-model artifact can be exchanged with the supported Java JSON model path. JavaScript-native forests and older artifacts are not automatically the same format just because they use six feature names.

Acceleration has a conversion cost

Python calls cross the native-extension boundary; JavaScript calls cross the WASM boundary. Converting object-heavy inputs consumes time before the Rust computation starts. Reusing matchers and processing sufficiently large feature batches can amortize that cost.

The Python bridge selects installed capabilities and retains fallback behavior. The Node adapter can choose JavaScript when WASM initialization or conversion is unsuitable. A native function returning a suspicious reason still requires the host to turn that result into a policy decision.

Worked example: accelerated header validation

The Python adapter receives framework headers and normalizes HTTP or WSGI key names. The bridge passes the resulting dictionary and validation options through PyO3. Rust evaluates the configured header rules and returns a reason or a clean result. The Python middleware then decides whether to return a response, record an offense, or continue to the handler.

The Rust core never sends the Flask or FastAPI response itself. This boundary explains why framework configuration and exemptions continue to matter when native acceleration is enabled.
