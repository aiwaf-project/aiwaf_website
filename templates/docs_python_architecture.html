Python Architecture and Request Lifecycle

Django, Flask, and FastAPI expose separate adapters over the shared Python core. The adapter owns framework execution; the core supplies route policies, state abstractions, detection helpers, and training primitives.

How AIWAF works: system architecture

Module boundaries

Source areaResponsibility
py/aiwaf/core/Shared exemptions, middleware planning, route discovery, storage, reputation, training, and native capability bridges.
py/aiwaf/django/Django middleware, ORM models, decorators, settings compatibility, and management commands.
py/aiwaf/flask/Flask application initialization, request/response hooks, stores, and CLI integration.
py/aiwaf/fast/FastAPI-facing exports and middleware; the shared orchestrator lives in core/runtime_fastapi.py.

Initialization and policy planning

Initialization normalizes settings, selects storage, and resolves the requested middleware set. middleware_plan.py expands canonical selections and applies disabled checks. Route discovery supplies hints such as UUID routes and application intent, while path_manifest.py loads generated path policies.

The resulting middleware plan determines which framework hooks are registered. A route plan then decides whether each registered protection applies to a particular request. Global enablement and per-route applicability are different questions.

How each adapter executes

AdapterRequest boundaryResponse boundary
DjangoThe configured MIDDLEWARE order determines nested request execution. The unified alias expands the AIWAF stack; individual classes permit explicit ordering.The framework unwinds response handling through middleware. Logging and checks that use outcomes need to observe that response.
Flaskflask_integration.py registers selected middleware objects and their Flask request hooks. A returned response stops normal handler dispatch.Response hooks observe the handler result for logging and relevant behavior checks.
FastAPIruntime_fastapi.py registers Starlette middleware in reverse order because the last registered wrapper executes first.Response control returns through the wrapper chain; the orchestrator coordinates configuration and lifecycle integration.

FastAPI's orchestrator documents the effective available chain as Geo, IP/keyword, Rate, AI, Honeypot, UUID, Header, and Logging. Disabled or inapplicable layers are skipped. Do not infer execution order from the order of add_middleware calls alone.

Following one request

  1. Resolve contextRead request metadata and the resolved endpoint where available.
  2. Apply route policyCheck path rules and endpoint exemption or protection metadata for each layer.
  3. Enforce selected checksConsult block state, counters, validation rules, and the available anomaly model.
  4. Observe outcomeAllow the handler or return a denial, then record the response through applicable hooks.

The exact shortcut behavior belongs to each middleware. An exempt path, an exempt client, a geo-only exemption, and a decorator disabling one check are distinct policies. Use the layer-specific decision to explain a bypass rather than assuming that every exemption disables the complete stack.

Live routes, manifests, and decorators

The CLI imports the actual application object or Django URL configuration and enumerates registered routes. Where handler source is available, static analysis adds method, API, form, and authentication signals. The generated .aiwaf/paths.json is a policy input, not a replacement router.

Manifest compilation creates path rules for middleware enablement and rate overrides. Explicit decorators carry endpoint intent: aiwaf_exempt, aiwaf_exempt_from, aiwaf_only, and aiwaf_require_protection. They complement global configuration. Regenerate a manifest when live registrations change so the policy does not describe an older application.

Storage and reputation

The shared runtime storage layer provides memory, JSON-file, CSV, and SQLite key-value implementations and typed stores for blocks, exemptions, keywords, and geo policy. Django and Flask also provide framework-specific database and CSV paths. A storage choice is adapter-specific; model storage is configured separately.

Reputation-based blacklisting stores weighted offenses, temporary-block escalation, expiration, and metadata. A later request reads that state rather than recomputing an entire traffic history. Legacy blacklist migration converts older schemas into the richer representation.

Memory is local to a process. Persisting an operational store does not automatically make every rate bucket or recent-request buffer distributed. FastAPI can supply a Redis-backed rate cache; review the storage semantics of the other enabled checks separately.

Training and scoring

total_404Not-found responses in the relevant per-client history.Repeated discovery of nonexistent routes.

The feature order is part of the model contract. A trainer and scorer must agree on the order, status mapping, time units, and window semantics. Summary fields ending in _ms use milliseconds; the feature vector uses seconds. Sharing feature names alone does not make every model artifact interchangeable.

  1. Request logsCompleted responses supply paths, client identity, status, and timing.
  2. Feature extractionRecords are normalized and combined with per-client activity windows.
  3. Train and reviewVolume thresholds gate model training; route exemptions filter learned keywords.
  4. Publish artifactsThe runtime loads persisted model state and updated learned keywords.

The training job is separate from ordinary application request handling. Reading logs and rebuilding a forest does not need to happen for every request. Runtime keyword learning, where enabled, is a separate mechanism that can use completed-response signals.

The trainer parses logs, extracts behavior, filters legitimate route tokens from keyword learning, and trains only when configured volume thresholds permit. Request-time scoring reads an available model; lack of a usable model does not remove deterministic header, rate, keyword, or geo controls.

Model artifacts carry forest state and metadata in JSON. Current Python persistence does not load pickle or joblib objects. That serialization boundary is separate from the choice of file, database, or cache for storing the artifact.

The Rust acceleration boundary

rust_backend.py discovers installed aiwaf_rust capabilities. A supported native operation can accelerate matching, header validation, feature extraction, or forest operations while the Python adapter continues to own the request and response.

The bridge normalizes HTTP and WSGI header names before calling native validation. If the extension or a capability is unavailable, the relevant Python fallback remains available. Native acceleration changes where a computation runs; it does not replace framework policy or storage.

Worked example: an API request and a scanner

A JSON API handler can carry route metadata that omits HTML form timing. Header and rate checks still apply when selected. Allowed requests reach the handler, and the logger records its actual result.

A scanner requesting many missing paths creates a different record: suspicious keyword hits, repeated 404s, and burst activity. Keyword or rate checks may reject it immediately. Sufficient logs later give the trainer behavior data for the anomaly path. Each decision should be explainable by its enabled layer and recorded reason.

System overview connects these components. The setup guides show wiring, and operations covers migration and training commands.
