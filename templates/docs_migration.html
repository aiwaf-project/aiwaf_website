Upgrade and Migration Guide

{% include '_docs_source.html' %}

All maintained packages use the AIWAF monorepo. Each package releases independently. Compare the installed version, source manifest, and release notes for your runtime before upgrading; source versions are not confirmation that a registry release exists.

Upgrade sequence

  1. Record installed versions, enabled middleware, exemptions, configuration, state backend, model path, and proxy behavior. Back up persisted state, configuration, and models.
  2. Upgrade one runtime in staging using its package manager or build from a reviewed source revision. Preserve the matching dependency lockfiles.
  3. Apply package-name and configuration changes below. Regenerate manifests from the live application after its routes are registered.
  4. Migrate blacklist state with the runtime's supported command; inspect counts, expiry, reasons, and exemptions afterward.
  5. Regenerate unsupported models with the current trainer. Verify schema, feature order, output location, and load diagnostics.
  6. Test normal public traffic, intentional blocks, rate boundaries, intended exemptions, and actual response logging. Test across workers when state is shared.
  7. Deploy code, configuration, and compatible state/models together. Reload workers and repeat checks. Keep a compatible rollback snapshot.

Node.js package name

The npm middleware package is now aiwaf. Replace the old dependency and imports; regenerate the lockfile and test every adapter entrypoint your application uses.

npm uninstall aiwaf-js
npm install aiwaf
const aiwaf = require('aiwaf');
app.use(aiwaf({ AIWAF_MIDDLEWARES: ['all'] }));

aiwaf-wasm remains a separate package. Installing it does not replace Node framework middleware. Check normalized aliases and defaults in the configuration reference before moving settings between versions.

Python reputation and blacklist data

Python 1.0.7 introduced weighted reputation, progressive temporary blocking, expiry, and richer metadata. Legacy blacklist compatibility is backend-aware, including CSV schema detection and conversion of imported permanent blocks. Use the same checkout, environment, and backend configuration as your application:

aiwaf blacklist migrate

Inspect aiwaf --help and the selected adapter's help when multiple frameworks are installed. Do not manually reinterpret old CSV columns or assume historical permanent blocks retain identical enforcement semantics. Back up first and compare the resulting entries.

Python models and Rust acceleration

Persisted Python runtime models are JSON. Pickle, joblib, and executable Python-object artifacts are unsupported; use representative logs and the current trainer to create a new model. Check minimum log thresholds rather than forcing production training on a tiny sample.

Python 1.0.8 requires aiwaf-rust>=0.2.1 for the Rust extra and fixes FastAPI header normalization and the disabled Rust-header path. Supported installed Rust capabilities are selected automatically, with Python fallback. Update the core package and accelerator together, and test header behavior in the real adapter.

python -m pip install --upgrade 'aiwaf[flask,rust]'
# Use the extra matching your application.
aiwaf flask train --help
aiwaf flask model --help

Route manifests and import targets

aiwaf init --framework flask --app app:app
aiwaf init --framework flask --app app:create_app
aiwaf init --framework fastapi --app app:app
aiwaf init --framework django --settings project.settings

--app app.py is invalid. The target must be a module and application object/factory. Run discovery in the application's environment; it imports the application. Do not carry a stale manifest across route changes.

Java 1.2 and 1.3 changes

Java 1.2 adds scoped per-engine storage, distributed Redis enforcement state, Spring Boot live route/annotation discovery, JSON/environment configuration, native MaxMind lookup, and updated reputation behavior. Remove the old requirement for an external mmdblookup executable. Review default private-address exemptions and manifest loading.

Java 1.3 adds bounded Redis connection/socket/pool waits, fail-open/fail-closed policy, diagnostics, and state-schema compatibility guards. It supports standalone Redis and rejects Sentinel/Cluster modes. Before a rolling upgrade, test old/new instances with the intended namespace and schema. Do not bypass compatibility guards or point unrelated services at one prefix.

Review legacy model feature schema against the current six-feature pipeline; retrain or use an explicit supported importer when required. Artifacts are not generally interchangeable between languages. Spring Boot applications should use the ordered filter once, rather than adding an independent interceptor as a second enforcement layer.

Rollback and release notes

Restore compatible code, configuration, state, and model artifacts together. Avoid reverting code while leaving a newer incompatible state schema. Repeat public-client and shared-worker checks after reload.

See the upstream changelog, Python operations, Node operations, and Java operations for runtime commands.
